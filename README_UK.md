# xlsx2txt

**Двосторонній конвертер між Excel (.xlsx/.xlsm) та текстовим JSON-форматом з повною підтримкою round-trip.**

На відміну від простих екстракторів тексту, xlsx2txt зберігає все — формули, стилі, об'єднані клітинки, VBA-макроси — і може повністю відновити оригінальний Excel-файл.

## Навіщо?

- 📊 **Git-friendly** — зрозумілі діфи для Excel-файлів
- 🔄 **Round-trip** — xlsx → text → xlsx без втрати даних
- 👁️ **Людиночитабельний** — JSON-формат для зручного перегляду
- ✅ **Верифікація** — вбудована перевірка цілісності

## Встановлення

Пакет поки не опублікований на PyPI. Встановлюйте з GitHub:

```bash
# останній реліз (підставте потрібну версію)
pip install https://github.com/click0/xlsx2txt/releases/download/v0.3.0/xlsx2txt-0.3.0-py3-none-any.whl

# або поточна гілка main
pip install git+https://github.com/click0/xlsx2txt.git

# з витягуванням коду VBA
pip install "xlsx2txt[vba] @ git+https://github.com/click0/xlsx2txt.git"
```

## Швидкий старт

```bash
# Експорт Excel у текстовий формат
xlsx2txt export report.xlsx ./report/

# Редагуйте JSON-файли або комітьте в Git
git add report/
git commit -m "Оновлення Q1 2025"

# Відновлення Excel-файлу
xlsx2txt import ./report/ report_new.xlsx

# Перевірка цілісності (контрольні суми + round-trip імпорт/експорт)
xlsx2txt verify ./report/
xlsx2txt verify ./report/ --against report.xlsx

# Порівняння двох експортів та/або Excel-файлів
xlsx2txt diff report.xlsx report_new.xlsx

# Коротка інформація про файл або каталог
xlsx2txt info report.xlsx
```

## Команди

| Команда | Опис |
|---------|------|
| `export FILE [DIR]` | Експорт `.xlsx`/`.xlsm` у каталог (за замовчуванням — ім'я файлу без розширення). `--no-cached-values` — не зберігати останні обчислені результати формул, `--force` — писати в непорожній сторонній каталог, `--mode debug` — показати записані файли. |
| `import DIR [FILE]` | Збирає Excel-файл (за замовчуванням — ім'я каталогу + оригінальне розширення). Не перезаписує існуючий файл без `--force`. |
| `verify DIR` | Перевіряє контрольні суми, внутрішню узгодженість і те, що дані переживають round-trip імпорт → експорт (`--no-roundtrip` — пропустити). `--against FILE` — додатково порівняти з Excel-файлом. Код виходу 1 при проблемах. |
| `diff A B` | Семантичне порівняння двох експортів або Excel-файлів (стилі порівнюються за вмістом, а не за індексом). `--ignore-cached` ігнорує кешовані результати формул. Код виходу 1, якщо є відмінності. |
| `info PATH` | Аркуші, кількість клітинок/формул, наявність VBA та непідтримуваних елементів. |
| `cat PATH` | Виводить Excel-файл або експорт як текст, по рядку на клітинку (`--no-styles`, `--no-cached-values`). Використовується для `git diff`, див. нижче. |

Ті самі операції доступні з Python:

```python
from xlsx2txt import export_xlsx, import_dir, verify_dir, load_model, diff_models

export_xlsx("report.xlsx", "report/")
import_dir("report/", "report_new.xlsx")
print(diff_models(load_model("report.xlsx"), load_model("report_new.xlsx")))
```

## Структура виводу

```
report/
├── manifest.json           # Версія формату, вихідний файл, попередження
├── data/
│   ├── workbook.json       # Властивості, порядок аркушів, імена, epoch
│   ├── sheets/
│   │   ├── _index.json     # Назва аркуша -> ім'я файлу
│   │   └── Sheet1.json     # Клітинки, формули, розміри, об'єднання, правила
│   ├── styles/
│   │   ├── fonts.json
│   │   ├── fills.json
│   │   ├── borders.json
│   │   ├── alignments.json
│   │   ├── protections.json
│   │   └── cellStyles.json # Комбінації, на які посилаються клітинки ("s")
│   ├── theme/theme1.xml    # Тема книги (кольори теми)
│   └── media/              # Зображення, названі за хешем вмісту
├── vba/                    # VBA-проєкт (для .xlsm)
│   ├── xl/vbaProject.bin
│   └── modules/*.bas       # Вихідний код VBA (лише для читання, потрібен oletools)
└── _verify/                # Дані верифікації
    └── checksums.json
```

Кожна клітинка записується окремим рядком, тож діфи в Git лишаються читабельними:

```json
"cells": {
  "A1": {"v": "Sales Report Q1 2025", "t": "s", "s": 1},
  "B3": {"v": 100, "t": "n"},
  "D3": {"t": "f", "f": "=B3*C3", "v": 999},
  "E3": {"v": "2025-03-14T00:00:00", "t": "d", "s": 3}
}
```

Ключі клітинки: `v` — значення, `t` — тип (`s` рядок, `n` число, `b` логічне,
`rs` форматований текст, `d` дата/час в ISO 8601, `td` тривалість у секундах, `e` помилка, `f` формула),
`f` — формула, `s` — індекс стилю в `cellStyles.json` (відсутній для стилю
за замовчуванням), `link` — гіперпосилання, `comment` — коментар. Для формул
`v` — останнє значення, обчислене Excel; воно довідкове й ігнорується при імпорті.

## Інтеграція з Git

Щоб `git diff` показував зміни всередині `.xlsx` без експорту:

```bash
echo '*.xlsx diff=xlsx' >> .gitattributes
echo '*.xlsm diff=xlsx' >> .gitattributes
git config diff.xlsx.textconv "xlsx2txt cat"
```

```diff
+B3: 150

```

## Обмеження

- Зведені таблиці та фігури поки не експортуються; `export` та `info`
  виводять попередження.
- VBA відновлюється з бінарного `vbaProject.bin`. Код у `vba/modules/`
  витягується лише для перегляду й діфів (встановіть `pip install xlsx2txt[vba]`);
  його редагування не змінює макроси.
- Налаштування драйвера принтера (`printerSettings*.bin`) та ланцюжок
  обчислень не зберігаються; останній Excel відновлює сам при відкритті.
  Прихований стовпець шириною 0 повертається зі стандартною шириною
  (але лишається прихованим).
- Діаграми зберігаються як XML у тому вигляді, який розуміє openpyxl;
  рідкісні можливості діаграм, яких openpyxl не підтримує, можуть втрачатися.
- Формули не перераховуються; Excel перерахує їх при відкритті файлу.

## Випуск релізу

Релізи робляться через веб-інтерфейс GitHub (workflow `.github/workflows/release.yml`):

1. Збільште `__version__` у `xlsx2txt/__init__.py` (версія пакета береться звідти) і злийте в `main`.
2. Далі або
   - **Actions → release → Run workflow**, введіть версію (напр. `0.1.0`); workflow прожене тести,
     збере wheel і sdist, створить тег `v0.1.0` і GitHub Release з файлами; або
   - **Releases → Draft a new release**, створіть тег `v0.1.0`, натисніть **Publish**; workflow прожене
     тести й додасть зібрані файли до цього релізу.
3. Публікація на PyPI (необов'язково): додайте [trusted publisher](https://docs.pypi.org/trusted-publishers/)
   на PyPI (workflow `release.yml`, environment `pypi`), потім позначте **pypi** при запуску workflow або
   задайте змінну репозиторію `PUBLISH_TO_PYPI=true` для релізів, створених на сторінці Releases.
